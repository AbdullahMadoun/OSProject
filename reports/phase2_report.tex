\section{Project Recap}

The project is a CPU scheduling simulator for an Operating Systems course. It
models a set of processes with arrival time, burst time, and priority, then
runs scheduling algorithms to show how process order affects waiting time,
turnaround time, response time, CPU utilization, throughput, and context
switching.

The implemented simulator supports:

\begin{itemize}
  \item First-Come, First-Served (FCFS)
  \item non-preemptive Shortest Job First (SJF)
  \item Round Robin with configurable quantum
  \item non-preemptive priority scheduling
\end{itemize}

The project is intentionally focused on operating-system scheduling behavior.
Earlier experimental prediction and cloud inference files were removed during
final Phase 2 cleanup so the repository now matches the scheduler-only project
scope.

\section{Challenges Faced}

\begin{itemize}
  \item \textbf{Consistent process timing:} Each algorithm updates start time,
  completion time, response time, and remaining time differently. A shared
  reset path was needed so comparison mode could run algorithms back-to-back.

  \item \textbf{Deterministic tie-breaking:} Scheduling algorithms can produce
  ambiguous results when several processes arrive together or share the same
  burst/priority. The implementation uses stable tie-breakers so tests and
  reports are reproducible.

  \item \textbf{Round Robin queue order:} Round Robin must add processes that
  arrive during a time slice and then decide whether to requeue the current
  process. That ordering affects response time, waiting time, and context
  switch counts.

  \item \textbf{Input validation:} The parser must handle normal workloads and
  malformed inputs without crashing. This required explicit rejection of bad
  integer fields, duplicate PIDs, invalid burst values, extra tokens, and NUL
  bytes.

  \item \textbf{Metric correctness:} Waiting time, turnaround time, and
  response time are easy to mix up. Tests were added around the formulas to
  keep output consistent.

  \item \textbf{Scope control:} A previous experimental prediction layer made
  the project look less focused. It has now been removed so the repository
  directly supports the Operating Systems Phase 2 requirements.

  \item \textbf{Validation gap:} Unit tests cover the main behavior, but they
  are not a proof of correctness for every possible workload. Fuzzing and
  memory-check evidence still need to be run and documented.
\end{itemize}

\subsection{Audit Result}

The final Phase 2 cleanup removed the underlying prediction code and remote
inference support from the repository. The active source tree no longer
contains the former model training files, prediction server, or model artifact.
The command-line interface also no longer exposes the old prediction flag.

The remaining Python code is helper tooling for this OS project:

\begin{itemize}
  \item \texttt{scripts/visualize\_runs.py}: builds HTML reports from simulator
  CSV output.
  \item \texttt{scripts/os\_process\_logger.py}: generates experimental
  simulator workloads from local process CPU samples.
  \item \texttt{tests\_py/}: verifies helper script behavior and CSV export.
\end{itemize}
