\section{Brief Project Recap}

The project is a command-line CPU scheduling simulator written in C. It
accepts a workload of processes, executes one scheduling algorithm or compares
all supported algorithms, builds a Gantt timeline, and reports standard
scheduling metrics. The simulator is intended to help compare scheduling
behavior using FCFS, non-preemptive SJF, Round Robin, and non-preemptive
priority scheduling.

The earlier machine-learning prediction idea has been removed from the Phase 2
scope. The current report therefore focuses only on the core operating-system
simulation: workload parsing, scheduler execution, timeline generation,
metrics, visualization, CSV export, and tests.

The main program parses command-line options, loads a workload, selects a
scheduler, and sends the process list into the common scheduling dispatcher.
Each scheduler updates process timing fields and appends execution intervals to
the simulation result. The metrics module then computes aggregate and
per-process measurements, and the visualization module prints the Gantt chart,
metric table, and comparison output.

\section{Challenges Faced}

\begin{itemize}
  \item \textbf{Consistent timing rules:} Each algorithm updates start time,
  completion time, response time, and waiting time differently. Keeping these
  fields consistent required a shared reset path and a metrics module that
  recomputes values from final process state.

  \item \textbf{Tie-breaking:} To make results deterministic, FCFS, SJF, and
  priority scheduling need stable tie-breaking rules. The implementation uses
  arrival time and PID where needed.

  \item \textbf{Round Robin arrivals:} Round Robin must add processes that
  arrive during a quantum and must requeue unfinished jobs without losing FIFO
  order.

  \item \textbf{Input validation:} The workload parser must reject malformed
  input, duplicate PIDs, zero or negative burst time, negative arrival time,
  negative priority, embedded NUL bytes, and extra tokens.

  \item \textbf{Scope cleanup:} The earlier ML prediction feature was removed
  from the current project plan, but some legacy files and README references
  still exist in the repository. These should be cleaned before final
  submission.

  \item \textbf{Context-switch accounting:} Context-switch overhead and
  context-switch counts need one final consistency pass across all algorithms
  before the final submission.

  \item \textbf{Verification limits:} Unit tests pass for the current cases,
  but long fuzzing campaigns and memory-leak evidence still need to be
  documented.
\end{itemize}

  source files, headers, tests, workloads, Makefile, and this report.
\end{enumerate}

The main source files include function-level organization and comments where
they clarify behavior. Additional comments should be added only where the final
implementation has non-obvious scheduling logic or validation decisions.

\section{Conclusion}

Phase 2 has produced a working C implementation of the core CPU scheduling
simulator. The main algorithms, workload parser, timeline generation, metrics,
terminal visualization, CSV export, and C unit tests are implemented and
working locally. The remaining work is primarily cleanup, documentation,
expanded validation, and final packaging.
